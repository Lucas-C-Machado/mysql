# 👋 Seja bem-vindo(a)!

Antes de tudo, muito obrigado pelo interesse em contribuir com este projeto.

O **Banco de Dados Relacionais** é um livro digital desenvolvido com o objetivo de tornar o aprendizado de Banco de Dados mais acessível, organizado e próximo da realidade profissional.

Toda contribuição é muito bem-vinda e ajuda este material a evoluir continuamente.

---

# 🎯 Como você pode contribuir?

Existem diversas formas de colaborar.

## 📝 Melhorias no conteúdo

Você pode sugerir:

- melhorias na escrita;
- correções ortográficas;
- ajustes de exemplos;
- reorganização de capítulos;
- explicações mais claras;
- novas analogias.

---

## 📚 Novos conteúdos

Também são bem-vindas sugestões como:

- novos capítulos;
- novos exercícios;
- estudos de caso;
- desafios;
- mapas mentais;
- diagramas;
- fluxogramas;
- tabelas comparativas.

---

## 🐞 Correções

Encontrou algum erro?

Abra uma **Issue** informando:

- capítulo;
- seção;
- descrição do problema;
- sugestão de correção (quando possível).

---

## 💡 Ideias

Gostou do projeto e teve uma ideia?

Quer sugerir um novo módulo?

Alguma tecnologia?

Outro estudo de caso?

Abra uma Issue.

Boas ideias sempre são bem-vindas.

# 🚀 Fluxo de contribuição

Sempre que possível, siga este fluxo.

```text
🍴 Fork do repositório
        │
        ▼
🌿 Criar uma nova branch
        │
        ▼
✏️ Realizar as alterações
        │
        ▼
✅ Revisar o conteúdo
        │
        ▼
📤 Enviar um Pull Request
```

---

# 🌿 Nomeando branches

Utilize nomes descritivos.

Exemplos:

```text
feature/novo-capitulo-normalizacao

feature/exercicios-select

feature/estudo-de-caso-escola

fix/correcao-capitulo-sgbd

docs/melhoria-readme

refactor/padronizacao-modulo-03
```

---

# ✍️ Padrões de escrita

Todo novo conteúdo deve seguir o **GUIA-DE-PADRONIZACAO.md**.

Em especial:

- linguagem simples;
- abordagem progressiva;
- foco no entendimento antes da implementação;
- exemplos práticos;
- analogias;
- exercícios;
- glossário;
- navegação entre capítulos.

---

# 📖 Estrutura esperada dos capítulos

Sempre que um novo capítulo for criado, recomenda-se seguir a estrutura abaixo.

```text

Objetivos

↓

O que será aprendido

↓

Explicação

↓

Analogia

↓

Exemplos

↓

Curiosidade

↓

```

# 🎨 Recursos visuais

Sempre que fizer sentido, utilize:

- tabelas;
- diagramas Mermaid;
- fluxogramas;
- mapas mentais;
- listas;
- caixas de destaque.

Nosso objetivo é tornar o aprendizado cada vez mais visual.

---

# 📚 Linguagem

Este projeto foi desenvolvido para pessoas que estão aprendendo Banco de Dados pela primeira vez.

Por isso, procure utilizar uma linguagem:

- clara;
- objetiva;
- acolhedora;
- didática;
- progressiva.

Evite assumir conhecimento prévio do leitor.

---

# 🚫 Evite

Sempre que possível, evite:

- textos excessivamente técnicos;
- jargões sem explicação;
- capítulos muito longos sem divisões;
- exemplos pouco contextualizados;
- código antes da explicação do conceito.

---

# ✅ Sempre procure

Ao escrever novos conteúdos, procure:

- explicar o conceito;
- contextualizar o problema;
- utilizar analogias;
- apresentar exemplos reais;
- reforçar os principais pontos;
- propor exercícios.

---

# 📦 Organização do projeto

Antes de criar novos arquivos, observe a estrutura do repositório.

```text
README.md
ROADMAP.md
CHANGELOG.md
GUIA-DE-PADRONIZACAO.md
CONTRIBUTING.md
LICENSE

01-fundamentos-de-banco-de-dados/
02-requisitos-e-modelagem/
03-mer-e-der/
04-normalizacao/
05-scripts-sql/
06-exercicios-e-desafios/
```

Mantenha essa organização sempre que possível.

---

# 📌 Antes de enviar um Pull Request

Verifique se:

- [ ] o conteúdo segue o Guia de Padronização;
- [ ] não existem erros de ortografia;
- [ ] os exemplos estão corretos;
- [ ] a navegação entre capítulos foi atualizada;
- [ ] os links funcionam corretamente;
- [ ] o Markdown foi renderizado corretamente.
