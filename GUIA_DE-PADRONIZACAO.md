# 📖 Objetivo deste documento

Este guia define os padrões utilizados em toda a documentação do projeto **Banco de Dados Relacionais**.

Seu objetivo é garantir que todos os módulos, capítulos e materiais mantenham:

- identidade visual;
- organização;
- sequência didática;
- consistência textual;
- experiência uniforme para o estudante.

Este documento deve servir como referência para qualquer conteúdo novo desenvolvido para este repositório.

---

# 🎯 Filosofia do projeto

Todo conteúdo produzido deve seguir três princípios fundamentais.

## 🧠 Primeiro compreender

O aluno precisa entender o problema antes da solução.

Nunca apresentar um comando sem explicar:

- por que ele existe;
- qual problema resolve;
- quando deve ser utilizado.

---

## 📐 Depois modelar

Sempre que possível, mostrar como a solução é construída.

Antes de escrever código:

- compreender o cenário;
- identificar requisitos;
- modelar entidades;
- organizar informações.

---

## 💻 Só então implementar

O código aparece apenas quando o estudante já compreendeu o conceito.

---

# 📂 Organização do repositório

Cada módulo possui sua própria pasta.

Exemplo:

```text
01-fundamentos-de-banco-de-dados/

README.md

01-apresentacao-do-modulo.md

02-dado-x-informacao.md

03-cadeia-de-valor-dos-dados.md

...
```

Cada pasta obrigatoriamente possui um README próprio.

---

# 📚 Estrutura obrigatória dos módulos

Todo módulo deve conter:

- README.md
- Introdução
- Objetivos
- Índice
- Estrutura
- Tempo estimado
- Recursos utilizados
- Navegação

# 🎯 Objetivos

Todo capítulo deve informar claramente:

Ao final desta leitura você será capaz de:

- compreender...
- identificar...
- diferenciar...
- aplicar...

---

# 📖 Explicação

Sempre iniciar pelos conceitos.

Evitar apresentar definições extremamente técnicas.

Dar preferência para:

- linguagem simples;
- frases curtas;
- construção progressiva.

---

# 🧠 Analogias

Todo conceito importante deve possuir pelo menos uma analogia.

Exemplos:

- biblioteca;
- supermercado;
- quebra-cabeça;
- armário;
- agenda;
- escola;
- hospital.

---

# 🚀 Exemplos

Sempre apresentar exemplos reais.

Preferencialmente utilizando empresas conhecidas.

Exemplos:

- Instagram
- Netflix
- Spotify
- Uber
- iFood
- Mercado Livre
- WhatsApp

---

# 🌎 Estudos de Caso

Sempre que possível incluir estudos de caso completos.

Estrutura sugerida:

Problema

↓

Dados

↓

Processamento

↓

Resultado

↓

Conclusão

---

# 💡 Curiosidades

Cada capítulo deve possuir pelo menos uma curiosidade.

Objetivo:

Tornar a leitura mais leve.

---

# ⚠️ Erros comuns

Todo capítulo deve alertar sobre erros frequentes.

Formato:

> Muitas pessoas acreditam que...

Na realidade...

---

# 📌 Resumo

Todo capítulo termina com um resumo.

Formato sugerido:

- conceito 1
- conceito 2
- conceito 3
- conceito 4

---

# 📝 Exercícios

Sempre incluir exercícios.

Misturar:

- verdadeiro ou falso;
- múltipla escolha;
- associação;
- desafios;
- situações práticas.

---

# 📚 Glossário

Todo capítulo termina com um glossário.

| Termo | Definição |
|--------|-----------|

# 🔗 Rodapé

Todos os capítulos terminam com navegação.

Exemplo:

```text
⬅️ Capítulo anterior

🏠 Índice do módulo

➡️ Próximo capítulo
```

# 🎨 Recursos visuais

Durante todo o material utilizar:

- emojis;
- diagramas;
- Mermaid;
- tabelas;
- fluxogramas;
- caixas de destaque;
- mapas mentais;
- exemplos visuais.

Sempre que um recurso visual facilitar a compreensão, ele deve ser utilizado.

---

# 📊 Diagramas

Dar preferência para Mermaid.

Exemplos:

- Flowchart
- Mindmap
- ER Diagram
- Sequence Diagram
- Timeline
- State Diagram

---

# ⏱️ Tempo estimado

Todo capítulo informa:

- tempo médio;
- dificuldade;
- pré-requisitos.

---

# 🧩 Linguagem

A linguagem deve ser:

- clara;
- objetiva;
- didática;
- amigável;
- progressiva.

Evitar:

- excesso de formalismo;
- frases longas;
- termos técnicos sem explicação.

---

# 🚫 Nunca fazer

Não apresentar código antes do conceito.

Não utilizar jargões sem explicação.

Não pular etapas do aprendizado.

Não assumir conhecimento prévio.

---

# ✅ Sempre fazer

Explicar.

Demonstrar.

Comparar.

Exemplificar.

Exercitar.

Revisar.

---

# 🏆 Missão deste projeto

Mais do que ensinar SQL, este material busca formar profissionais capazes de compreender como os Bancos de Dados funcionam, modelar soluções e desenvolver sistemas de forma consciente.

Toda decisão de escrita, organização ou conteúdo deve respeitar essa missão.
